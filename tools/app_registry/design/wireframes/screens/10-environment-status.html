note: rows are exactly the `PROMOTABLE` targets (chart artifacts, and standalone `image`-deploy-unit apps like leaflab-gateway) — a `NOT_PROMOTABLE` app (e.g. app-registry-api itself, build-only) never appears here at all. `VIA_CHART` apps only ever surface nested, under the chart that publishes them, and only ever get "override…"/"edit…" — never the primary ⬆ Promote button — so promoting the wrong artifact class takes a deliberate extra step, not an accidental click. Every ⬆/↺ opens already scoped to its exact (entity, environment) pair; nothing in this flow ever asks "which environment?" Assumes ≤4-5 environment columns fits before this needs to become "only render a column when it's a valid target for this row" — "not applicable" (leaflab-gateway / prod) is that fallback in miniature. Implementation note: a real build should stop a click on a nested action from also toggling the row's `<details>` open/closed state (event handling `<details>`/`<summary>` can't do statically) — not a concern for this static mockup.
