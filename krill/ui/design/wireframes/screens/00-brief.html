krill UI facelift: brief

Audience and jobs

Who: operators and engineers running agent swarms against a product spec. Developer-grade density is fine; IDs are allowed but secondary.

  1. See what is stuck or escalated and act on it (release, requeue, cancel).
  2. Follow a milestone: what shipped, what is left, which tasks are in which lane.
  3. Review a design session: revisions, open questions, answer the blocking ones.

Five-second answer on landing: "Is anything stuck, and which milestone is in flight?"

Object tree and verbs

  • Product (switch) → Milestone (amend status, view breakdown) → Milepebble → Task (release, requeue, escalate, cancel)
  • Task facets: dependencies, notes, attempts and claim, spec slice
  • Product → Design session (open, answer questions, follow up) → revision events
  • Product → Spec: feature sets, features, requirements, decisions, personas, non-goals (read-only)
  • Admin: static bearer credentials for MCP clients (mint, revoke)

Archetype: workspace

Six areas and a four-level object tree. Sidebar groups follow the tree; the product switcher replaces typing a product id. Detail pages get a properties rail.

First proof of the proposed workspace shell. Note that app-exemplars.md still lists krill as off-stack; it is already on templ + htmxui.

What changes versus today

  • Landing pages become "at a glance" instead of link-and-blurb lists.
  • Task and ops lists become real tables; lanes, states and verdicts are badges.
  • Board scrolls horizontally on narrow screens instead of a fixed 5-column grid.
  • Task detail gets a properties rail; raw spec JSON moves behind a disclosure.
  • Cancel confirmation moves from a separate page to an in-row confirm.
  • UUIDs become copy chips; timestamps become relative with the exact time on hover.
  • Design sessions open from the product switcher, never a typed product id.

Open: today's ops queues are scoped by delivery (milestone/milepebble). The sidebar shows them product-wide; confirm the read API supports a product-level scope or keep a milestone filter.
